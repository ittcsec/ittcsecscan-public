# Release notes: v0.2.0-rc.1

This release candidate widens read-only collection across all three clouds, adds two new
detection-pack families (identity hygiene and AI Guard), maps the new identity-hygiene rules to
compliance frameworks, and adds trust, diff, and compliance views over real findings. It remains
local-first, read-only by default, deterministic, and honest: a denied, throttled, unsupported, or
errored read is always a represented gap, never a silent pass.

## New capabilities

### Wider read-only collection

- **AWS**
  - IAM credential report: per-user and per-access-key last-used, access-key age, MFA state, and
    root-account use, plus role last-used from `GetAccountAuthorizationDetails` (dormant-credential
    signal).
  - VPC endpoint resource policies (cross-account and exfiltration surface).
  - Public EBS snapshot detection (`createVolumePermission=all`).
  - Lambda function URLs and resource policies (environment values are structurally stripped, never
    collected).
  - S3 access points (network origin, public status, policy), using the account's real region
    opt-in status from `ec2:DescribeRegions` rather than inferring from an access denial.
  - Bedrock AI agent inventory (agents, action groups, knowledge bases, data sources).
- **Azure**
  - Tenant security defaults and Conditional Access posture (via `Policy.Read.All`; on an
    unlicensed tenant Conditional Access reports Unsupported, never a pass).
  - App registration credential expiry and credential lifetime in days.
  - Application permission (app-role) assignments for service principals, with each permission id
    resolved from the resource app's own catalog (an unresolved id is recorded, never guessed).
  - Dropped the redundant `GroupMember.ReadBasic.All` Graph permission; `Group.Read.All` suffices.
- **GCP**
  - Workload identity federation pools and providers.
  - User-managed service-account key age (dormant-credential signal).
  - Effective org policy for a curated set of security constraints (an unknown or list-type
    constraint is recorded and rendered as unknown, never as not-enforced; a project-scoped service
    account cannot see organization-level policy).

### Detection

- **Identity-hygiene pack (10 rules):** AWS user and root MFA, access keys unused and unrotated, an
  active root access key, dormant roles; Azure app credentials expired or expiring and over-long
  credential lifetime, and high-impact Microsoft Graph permission grants; Google Cloud user-managed
  service-account key age. Numeric thresholds live in the signed rule data, not in collectors, so
  changing a threshold re-signs a rule.
- **Per-node honesty gate (`indeterminate`):** a node whose deciding fact is missing, a sentinel, or
  an unresolved permission id is reported Unknown, never a pass.
- **Signed and embedded packs:** the `identity-hygiene` and `ai-guard` packs are now signed by the
  offline pack key and embedded, so a real scan loads and evaluates them fail-closed under the key
  in `packs/keys/allowed_signers`. An unsigned, tampered, wrong-key, or wrong-namespace built-in
  pack is refused.

### Compliance, trust, and views

- **ITTCsecProof compliance mappings** for the identity-hygiene rules: control identifiers only,
  mapping each rule to ISO 27001 (2022) and SOC 2, plus NIS2, DORA, and GDPR where an exact article
  applies. Coverage is an evidence map, never a certification.
- **ITTCsecTrust**, a shareable signed trust report; `verify-trust`, in-process fail-closed
  signature verification; `diff`, surfacing later-scan change detection; a visual attack-path
  diagram in the HTML report; and a zero-egress audit mode (`scan --offline-audit`).

## Change detection: AGE-FACTS-2 one-time re-baseline

Age-in-days facts (keys ending `_age_days`, plus `days_until_expiry`) advance on their own every
day. The later-scan change detector now hashes a stable view of each entity's attributes that
excludes those volatile keys, so a pure daily age tick is no longer reported as a change while a
real change (a rotated key's new last-rotated date, a new or removed credential, a granted
permission) still is.

`content_hash` is an internal change-detection artifact, not a schema field, so this needs no
migration and old databases keep loading. There is one visible effect: on the **first** later scan
run with this version, every entity that carries a volatile fact and was last stored by the previous
version is recorded as changed exactly once (its hash is recomputed the new way), then settles.
Entities with no volatile fact are unaffected. This is a self-correcting one-time re-baseline, not
data loss.

## Remediation gaps on the new rules

Remediation stays plan-only (the `fix` command prints doc-verified plans and never changes a cloud).
The 13 rules in the two new packs ship with a specific, tracked **named gap** rather than an
apply-ready template: each states the concrete manual fix and why it is not auto-generated (it
depends on operator intent, or on an interactive, unscopable sign-in). No finding falls back to a
generic gap. Apply-ready CLI and IaC templates for these rules are planned follow-up work (see
IDH-1 in `docs/known-limitations.md`).

## AI Guard status

AI Guard is a first slice and is **fixture-only**: the three rules (excessive agent privilege,
unsafe tool, dangerous data access) are implemented and unit-tested against recorded Bedrock agent
API shapes, but have not been exercised against a live AI agent in this project's environment. On a
real scan, when the agent inventory cannot be fully read these rules report Unknown (not checked)
rather than a pass. The Bedrock collector's authentication, region handling, and gap classification
are live-verified; only the agent parsing is fixture-only.
